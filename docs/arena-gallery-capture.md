# 競技場圖庫擷取指南

這份文件定義 README 與遊戲地圖選擇器所共用的三十六張實機預覽圖如何拍攝、驗證與更新。
地圖幾何、材質、光照、載具、目標物或主要取景改變後，必須重新擷取受影響的地圖；大規模幾何或
多邊形密度更新則應重拍全套。日後新增的地圖也必須加入 `Maps.ArenaCaptureFiles`、擷取腳本的
檔名表與這套驗證程序。

## 一鍵擷取

在儲存庫根目錄執行：

```powershell
pwsh .\docs\capture-arenas.ps1
```

完整執行會建立目前 Release 版本，逐張輸出無 HUD 的 1920×1080 PNG，再縮為 960×540、品質 82
的 JPEG，寫入 `docs/arenas/`。README 直接引用這些檔案，而建置程序也會把相同檔案嵌入遊戲，
因此文件與地圖選擇器不會各自產生不同的隨機畫面。

只重拍特定地圖可傳入穩定的 `MapId` 數字：

```powershell
pwsh .\docs\capture-arenas.ps1 -Maps 15,21,25,28
```

若已人工檢查 `%TEMP%\unreal99-arena-shots\mapN.png`，只要重新轉換現有 PNG：

```powershell
pwsh .\docs\capture-arenas.ps1 -Maps 15,21 -ConvertOnly
```

`-ConvertOnly` 不得用來掩蓋過期或空白的來源圖；腳本會拒絕不存在或小於 1 KiB 的 PNG。

## 遊戲模式與取景

每張圖都以地圖原本設計的模式執行，確保正式的目標物和模式專用物件存在：

- 0～12：死亡競賽
- 13～16：奪旗大戰
- 17～20：支配佔領
- 21～24：攻堅模式
- 25～27：突擊模式
- 28～33：戰爭模式
- 34～35：炸彈球

一般地圖以自動巡航鏡頭或 `--flycam 半徑 高度 角度 注視高度` 的人工參數取景。每張人工參數與
選角原因都記在 `docs/capture-arenas.ps1` 的 `$authored` 表，修改圖片時必須同步修改該表，不能只
保留一次性的命令。面對世界（15）是特別構圖：鏡頭必須在橋側的斜角遠景中同時拍到兩座互相面對
的塔樓，不得沿橋正面拍成只有一座塔的平面畫面。

## 載具地圖

有載具的地圖為 21～25、27～33；26（AS-護衛艦）沒有載具。這些圖不可等電腦把載具開走後才拍，
也不可只拍到空停機坪。腳本會以一位閒置的人類玩家、零名電腦啟動正式模式，讓全部載具生成並
留在出生點，再使用：

```text
--vehicleflycam 角度 [載具出生點編號]
```

腳本同時傳入 `--nodemo`，覆寫使用者可能已儲存的示範模式設定，確保本機玩家不會代打並開走載具。
此鏡頭會找出半徑 38 公尺內最密集的載具群，以群組中心與分布寬度自動計算視點距離及高度；如果該群
位於屋頂或結構內，可追加 `VehicleSpawn` 編號改選另一群。腳本的 `$vehicleCameras` 為每張圖保存不受
車庫、塔樓或山崖遮擋的觀看角度及選用編號。快門固定在第 400 格，足以
完成關卡載入和倒數，但因沒有電腦操控，載具仍在原位。最終 JPEG 中至少一輛正式載具必須可清楚
辨識，且背景仍需呈現該地圖的主要地貌。

## 目視驗收

提交前逐張打開新的 JPEG，至少確認：

1. 圖片不是全黑、全白、載入畫面或碰撞體外側。
2. 地圖的主要上下層、路線或地標可辨認；屋頂、牆壁、地板或其他前景平面不得占據大部分畫面，
   也不得遮住應展示的載具或主要地標。
3. 模式專用地圖顯示正確的節點、目標標記、能量球、球或旗幟，且沒有旗幟懸空等錯置物件。
4. 所有載具地圖都清楚拍到載具；面對世界同時拍到兩塔。
5. README 與遊戲地圖選擇器顯示的是同一批更新後的 `docs/arenas/*.jpg`。
6. JPEG 為 960×540，沒有 HUD、第一人稱武器、滑鼠游標或偵錯文字。

擷取會使用正常桌面游標模式，不會鎖定、置中或移動使用者的游標。若單一執行個體鎖已被另一個
遊戲程序占用，腳本會因未產生新 PNG 而失敗，不能把舊檔誤當成本次成果。
